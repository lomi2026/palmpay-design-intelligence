# PalmPay体验设计Hub V1.0 — Product Requirements Document

## 1. 产品目标

V1.0 的目标是将最终 v9-1 高保真交互原型升级为可正式运行的内部产品。

核心目标：

1. 建立团队统一的设计资产入口。
2. 将有效 AI 工作方法沉淀为标准化 AI Skill。
3. 建立内容创建、审核、发布、维护和归档机制。
4. 建立真实搜索、收藏、使用和项目引用行为。
5. 建立设计能力复用和 AI 价值验证口径。
6. 为后续在线 AI Skill 和知识检索提供正式底座。

## 2. 产品原则

- 内容质量优先于数量。
- 正式内容必须有负责人、版本、状态和更新时间。
- AI 只辅助，设计师保留最终判断。
- 浏览不等于使用。
- 收藏不等于复用。
- 价值必须能追溯到真实项目或验证证据。
- 先解决高频真实工作，不建设大而全的平台。

## 4. 权限原则

1. 页面权限与 API 权限同时校验。
2. 作者不能审核自己的内容。
3. 审核人只能处理授权范围内内容。
4. 未发布内容仅作者、审核人和管理员可见。
5. 敏感内容支持团队或指定范围可见。
6. 管理员关键操作必须记录审计日志。
7. 正式内容使用软删除、下架或归档，不直接物理删除。

## 9. 核心流程

### 9.1 内容治理

```text
新建内容
→ 保存草稿
→ 完整度检查
→ 提交审核
→ 审核中
→ 通过 / 退回修改
→ 发布
→ 持续维护
→ 下架 / 归档
```

主状态：

```text
DRAFT
→ IN_REVIEW
→ CHANGES_REQUESTED
→ IN_REVIEW
→ APPROVED
→ PUBLISHED
→ UNPUBLISHED / ARCHIVED
```

### 9.2 资产复用

```text
产生任务
→ 搜索或筛选
→ 查看详情
→ 判断适用性
→ 收藏 / 下载 / 复制
→ 确认使用
→ 关联真实项目
→ 提交效果反馈
```

### 9.3 AI Skill

V1.0 基础流程：

```text
查找 Skill
→ 查看输入要求
→ 查看输出结构
→ 查看人工复核要求
→ 复制 Prompt
→ 在授权 AI 工具中执行
→ 返回平台确认使用
```

后续在线执行：

```text
选择 Skill
→ 输入材料
→ 确认数据安全
→ AI 执行
→ 查看结构化结果
→ 人工复核
→ 导出或保存
→ 提交反馈
```

### 9.4 AI 案例

```text
创建案例
→ 关联 Skill 和项目
→ 记录原问题
→ 记录 AI 介入节点
→ 记录人工判断
→ 上传结果证据
→ 审核
→ 发布
```

- 审核历史不可覆盖
- 超时触发提醒

## 15. AI 能力路线

### 阶段一：内容辅助

- 生成摘要
- 推荐分类
- 推荐标签
- 完整度检查
- 重复内容检查
- Skill 人工复核规则检查
- 案例验证证据检查

AI 仅提供建议，用户确认后写入。

### 阶段二：首批在线 Skill

优先：

1. PRD 设计分析
2. UI 还原度验收
3. 设计规范结构化

### 阶段三：连接设计工作流

优先连接：

- Figma
- 语雀
- Jira 或内部项目系统
- 企业消息工具
- GitHub

### 阶段四：设计知识检索

- 基于已发布资产回答
- 显示引用来源
- 优先当前有效版本
- 识别废弃内容
- 根据角色和场景推荐
- 识别知识缺口

## 16. V1.0 上线验收

必须满足：

1. 企业登录可用。
2. 角色权限完成越权测试。
3. 四类内容可真实创建和发布。
4. 内容审核闭环可用。
5. 文件存储与访问权限可用。
6. 搜索可检索正式内容。
7. 收藏和提交不依赖 localStorage。
8. 数据洞察读取真实事件。
9. 管理员操作有审计日志。
10. v9-1 核心内容完成迁移。
11. 演示数据与正式数据隔离。
12. 核心 E2E 测试通过。
13. 数据库完成备份与恢复验证。
14. 阻断级与严重问题清零。

## 17. 上线后 8—12 周验证指标

- 目标设计成员周活跃率达到 50%
- 60% 以上用户产生搜索或详情查看
- 30% 以上用户产生收藏、复制或使用行为
- 正式发布不少于 20 项核心设计资产
- 正式发布不少于 10 个 AI Skill
- 至少 3 个 Skill 被真实项目使用
- 至少形成 3 个带验证证据的 AI 案例
- 平均审核周期不超过 3 个工作日
- 能识别并处理高频无结果搜索需求
